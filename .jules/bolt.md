## 2026-05-21 - Array.prototype.forEach Closure Allocation Optimization
**Learning:** In hot loops executed 60 times per second (like MovementSystem.ts and EntityRenderer.ts), using Array.prototype.forEach causes severe garbage collection pressure and function invocation overhead due to per-element closure allocations, even with empty arrays.
**Action:** Always replace `forEach` with standard `for (let i = 0, len = arr.length; i < len; i++)` loops for any array processing in systems running on every frame (tick/update/render). This eliminates the closure overhead completely. Always include an undefined guard clause (`if (element === undefined) continue;`) to maintain the same sparse-array safety as forEach, and always leave an explanatory comment to prevent future refactoring reversions.
