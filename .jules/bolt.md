## 2024-06-02 - Eliminate Closure Allocations in Physics Hot Loops
**Learning:** In high-frequency loop paths (e.g., 60 FPS update loops in physics systems like `MovementSystem.ts`, `CollectionSystem.ts`, and `CombatResolutionService.ts`), using `Array.prototype.forEach` creates closure function allocations on every iteration. This leads to rapid generation of transient objects and increases garbage collection (GC) pressure, which can cause micro-stutters.
**Action:** Replace `Array.prototype.forEach` with standard `for` loops (e.g., `for (let i = 0, len = arr.length; i < len; i++)`) in hot paths. Include a guard clause (e.g., `if (entity === undefined) continue;`) to prevent runtime TypeErrors from sparse arrays or concurrently modified pools, and translate any inner `return` statements to `continue`.
