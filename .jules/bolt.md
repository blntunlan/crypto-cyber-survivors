## 2025-02-20 - [Zero-Allocation Optimization for Targeting System]
**Learning:** In hot loops like the CombatSystem targeting logic which runs multiple times per frame, using `SpatialGrid.forEachInRange` with inline arrow functions allocates a new closure on every call. Additionally, tracking state (like best candidates) with intermediate allocated objects (e.g. `{ x, y, distSq, speed }`) increases garbage collection pressure, leading to frame drops.
**Action:** Always use the context-aware spatial grid queries (`forEachInRangeWithContext` or `forEachNearbyWithContext`) combined with a static pre-allocated context object (e.g., `TARGETING_CONTEXT`). Avoid allocating intermediate tracking objects inside the loop by storing tracking variables directly on the static context and allocating the final returned target object only once the loop has completed.
