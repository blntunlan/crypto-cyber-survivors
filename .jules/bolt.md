## 2024-05-18 - [Optimization] Replace .forEach with for loops in hot paths
**Learning:** Found several `.forEach` loop usages in hot paths (update loops and render loops), specifically in `MovementSystem.ts` and `EntityRenderer.ts`. In hot loops (e.g. 60 FPS update loops), using `.forEach` leads to closure function allocations and GC pressure.
**Action:** Replace `Array.prototype.forEach` with standard `for` loops in hot path functions. Guard against sparse arrays by checking if the element is undefined, which is a common pattern in Object Pooling implementations in this codebase.

## 2024-05-18 - [CI Issue] framer-motion peer dependency issues during Vite build
**Learning:** Updating framer-motion versions can result in `activeAnimations is not exported by motion-dom` Rollup errors during `vite build`. It's better to avoid touching root project dependencies if not required.
**Action:** Reverted framer-motion additions and avoided committing `pnpm-lock.yaml` regenerated by local testing tools, which is known to cause out-of-sync Node issues. The `railway-market-server` and `railway-market-aggregator` workspaces require their own lockfile synchronization but weren't strictly necessary for the client-side micro-optimization. Keep optimizations isolated.
