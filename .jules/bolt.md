## 2024-10-24 - Zero-Allocation Iteration in High-Frequency Physics Loops
**Learning:** In hot loops like `MovementSystem.update()` and `CollectionSystem.update()`, using `Array.prototype.forEach` introduces hidden closure allocations and function invocation overhead on every iteration. This creates noticeable garbage collection (GC) pressure when scanning arrays of hundreds or thousands of entities 60 times per second.
**Action:** Replace `Array.prototype.forEach` with a standard indexed array `for` loop (e.g., `for (let i = 0, len = arr.length; i < len; i++)`). Always cache the array length in the initialization block to mimic `forEach`'s behavior (ignoring elements pushed during iteration) and use a guard clause (`if (element === undefined) continue;`) to protect against sparse array indices flagged by `noUncheckedIndexedAccess`.
