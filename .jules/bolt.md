## 2024-05-18 - Zero-Allocation Viewport Bounds in Renderers
**Learning:** `createViewportBounds` was allocating a new object every frame across multiple renderers and targeting systems, causing unnecessary garbage collection pressure in hot loops. While individually small, combined across `EntityRenderer`, `ProjectileRenderer`, `EffectRenderer`, `CombatSystem`, and `WeaponFiringPipeline`, these allocations add up to frame stuttering during intense gameplay.
**Action:** Use a persistent, module/instance-level `ViewportBounds` object and mutate it in-place using a new `updateViewportBounds` function in `CullingUtils.ts`. Because JavaScript is single-threaded, mutating a shared object synchronously during a render tick is entirely safe and guarantees zero allocation per frame.
