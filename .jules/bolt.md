## 2024-04-15 - Hot Loop Function Allocations
**Learning:** High-frequency loop paths (e.g. `render` in `EntityRenderer.ts`) use `Array.prototype.forEach`. This allocates a closure function for every frame, putting pressure on the Garbage Collector and causing potential frame drops. Memory context says: "In high-frequency loop paths (e.g., 60 FPS update loops in physics systems like MovementSystem.ts and renderers like EntityRenderer.ts), replace Array.prototype.forEach with standard for (let i = 0, len = arr.length; i < len; i++) loops to avoid closure function allocations and GC pressure. When converting, ensure return statements within the forEach callback are translated to continue to properly preserve the flow logic. Specialized zero-allocation iterators like SpatialGrid.forEachNearby are exceptions."
**Action:** Replace `forEach` with a standard `for` loop, translating `return` to `continue`.
