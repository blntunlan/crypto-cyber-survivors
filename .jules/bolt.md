## 2024-10-10 - Zero-allocation spatial grid queries in combat systems
**Learning:** Inner-loop closure and object allocations (e.g. `let bestCandidate = { ... }` or passing a dynamic arrow function) in high-frequency queries like `enemyGrid.forEachInRange` cause frame-by-frame GC pressure in synchronous game loops. Additionally, `npm install` inside subdirectories can inadvertently update lockfiles and trigger a simulated code review failure.
**Action:** Extract closures into static functions utilizing module-level pre-allocated context objects (e.g., `TARGETING_CONTEXT`) with primitive fields for `forEachInRangeWithContext` loops to eliminate GC overhead. Also, revert any `package-lock.json` modifications caused by `npm install` before submission unless explicitly tasked to resolve a CI lockfile sync error.
