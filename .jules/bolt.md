## 2024-05-26 - Avoid Array.prototype.forEach in hot object pool loops
**Learning:** In high-frequency 60 FPS physics loops like `MovementSystem.ts`, using `Array.prototype.forEach` on large object pools causes unnecessary function closures to be allocated and rapidly garbage collected, causing GC pressure and potential stuttering. Manual loop unrolling is not recommended as V8 may de-optimize it, but standard `for` loops are much faster. Furthermore, when iterating over object pools, the arrays can be sparse or concurrently modified, so it's critical to include a guard clause like `if (entity === undefined) continue;` to prevent `TypeError`s during iteration.
**Action:** When working on physics or rendering hot paths (`MovementSystem.ts`, `EntityRenderer.ts`, etc.), always prefer standard `for (let i = 0, len = arr.length; i < len; i++)` loops over `forEach`, and always check `undefined` for object pool entities.
