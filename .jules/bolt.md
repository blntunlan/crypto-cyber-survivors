## 2026-06-13 - Zero-Allocation Loops in Physics Systems\n**Learning:** High-frequency loop paths (like `MovementSystem.update`) traversing array pools generate GC pressure when using `Array.prototype.forEach` due to closure allocations. Manual `for` loop conversions successfully mitigate this, but require explicit `undefined` guard clauses to prevent runtime TypeErrors from sparse arrays.\n**Action:** When optimizing loop constructs over object pools in rendering or physics systems, replace `forEach` with traditional `for` loops, always including `if (element === undefined) continue;`, and converting `return` logic to `continue`.
